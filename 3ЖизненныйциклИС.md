## 1. Цели и задачи

Цель лекции — разобраться, что такое жизненный цикл информационной системы и из каких этапов состоит её проектирование.

Задачи:
- понять, что вкладывается в понятие «жизненный цикл ИС»;
- рассмотреть этапы жизненного цикла;
- изучить основные этапы проектирования;
- познакомиться со стандартами, которые регулируют жизненный цикл.

Компетенции, которые формируются:
- ОК 01 — выбирать способы решения задач профессиональной деятельности;
- ОК 02 — использовать современные средства поиска и анализа информации;
- ПК 3.1 — разрабатывать проектные решения для информационной системы.

## 2. Что такое жизненный цикл ИС

Жизненный цикл информационной системы — это период от момента, когда появилась идея создать систему, до момента, когда её окончательно выводят из эксплуатации.

В жизненный цикл входят:
- анализ потребностей;
- проектирование;
- разработка;
- внедрение;
- эксплуатация;
- сопровождение;
- вывод из эксплуатации.

Зачем вообще выделять жизненный цикл? Это помогает:
- понять, какие этапы проходит система;
- спланировать работу, сроки и бюджет;
- распределить ответственность между участниками;
- контролировать качество на каждом этапе;
- документировать процесс создания.

Участники жизненного цикла:

| Роль | Чем занимается |
|------|----------------|
| Заказчик | Формулирует требования, принимает результат |
| Аналитик | Собирает и анализирует требования |
| Архитектор | Проектирует архитектуру системы |
| Дизайнер | Проектирует интерфейс |
| Разработчик | Пишет код |
| Тестировщик | Проверяет качество |
| DevOps | Обеспечивает развёртывание |
| Администратор | Поддерживает работу системы |

## 3. Этапы жизненного цикла ИС

Общая схема выглядит так:

```
Анализ → Проектирование → Разработка → Тестирование → Внедрение → Сопровождение → Вывод
   ↑                                                                              │
   └──────────────────────── обратная связь ──────────────────────────────────────┘
```

Разберём каждый этап.

### 3.1. Анализ требований

На этом этапе изучают предметную область, собирают требования от заказчика и пользователей, формулируют функциональные и нефункциональные требования, составляют техническое задание.

Что получается в итоге:
- техническое задание;
- спецификация требований;
- модели бизнес-процессов (IDEF0, DFD);
- диаграммы вариантов использования.

Кто участвует: аналитик, заказчик, пользователи.

### 3.2. Проектирование

Здесь разрабатывают архитектуру системы, проектируют базу данных, интерфейс, интеграции, документируют проектные решения.

Что получается:
- архитектурная документация;
- ER-диаграммы;
- UML-диаграммы;
- макеты интерфейса (wireframe, mockup);
- технический проект.

Кто участвует: архитектор, проектировщик БД, дизайнер.

### 3.3. Разработка

Пишут код, создают базу данных, реализуют интерфейс, интегрируют компоненты, проводят Code Review.

Что получается:
- исходный код;
- скомпилированные модули;
- миграции БД;
- документация API.

Кто участвует: разработчики, DevOps.

### 3.4. Тестирование

Проводят модульное, интеграционное, системное, регрессионное тестирование, проверяют безопасность и нагрузку.

Что получается:
- тест-кейсы;
- баг-репорты;
- отчёты о тестировании.

Кто участвует: тестировщики, разработчики.

### 3.5. Внедрение

Устанавливают систему у заказчика, настраивают окружение, переносят данные, обучают пользователей, проводят опытную эксплуатацию.

Что получается:
- инструкция по установке;
- руководство пользователя;
- акт внедрения.

Кто участвует: DevOps, администраторы, аналитик.

### 3.6. Сопровождение

Оказывают техническую поддержку, исправляют ошибки, обновляют и дорабатывают систему, следят за её работой, оптимизируют.

Что получается:
- патчи и обновления;
- отчёты о поддержке;
- журналы мониторинга.

Кто участвует: поддержка, разработчики, администраторы.

### 3.7. Вывод из эксплуатации

Отказываются от использования системы, архивируют данные, переносят их в новую систему, демонтируют инфраструктуру.

Что получается:
- акт о выводе;
- архив данных.

Кто участвует: администраторы, заказчик.

## 4. Основные этапы проектирования ИС

Проектирование — это второй этап жизненного цикла. Он включает несколько направлений.

### 4.1. Проектирование архитектуры

Выбирают тип архитектуры (монолит, клиент-сервер, микросервисы), определяют слои (UI, бизнес-логика, данные), описывают компоненты и их взаимодействие, выбирают технологии.

Результат: архитектурная схема и документация.

### 4.2. Проектирование базы данных

Анализируют данные предметной области, строят ER-диаграмму, нормализуют (1НФ, 2НФ, 3НФ), создают схему БД, проектируют индексы и связи.

Результат: схема БД и SQL-скрипты.

### 4.3. Проектирование пользовательского интерфейса

Анализируют пользователей и сценарии, проектируют навигацию, создают wireframe, mockup, интерактивный прототип, разрабатывают дизайн-систему.

Результат: макеты, прототипы, гайдлайны.

### 4.4. Проектирование интеграций

Определяют внешние системы, проектируют API, форматы обмена данными (JSON, XML), очереди сообщений, безопасность.

Результат: документация API и схемы интеграции.

### 4.5. Проектирование безопасности

Продумывают аутентификацию и авторизацию, шифрование данных, защиту от атак (SQL-инъекции, XSS), аудит действий, резервное копирование.

Результат: политика безопасности и документация.

## 5. Стандарты, регламентирующие ЖЦ ИС

### Российские стандарты

| Стандарт | Что регламентирует |
|----------|--------------------|
| ГОСТ 34.601-90 | Стадии создания автоматизированных систем |
| ГОСТ 34.602-89 | Техническое задание на создание АС |
| ГОСТ 19.102-77 | Стадии разработки программ |
| ГОСТ 19.201-78 | Техническое задание |
| ГОСТ Р 57193-2016 | Процессы жизненного цикла |

ГОСТ 34.601-90 выделяет восемь стадий:
1. Формирование требований к АС.
2. Разработка концепции АС.
3. Техническое задание.
4. Эскизный проект.
5. Технический проект.
6. Рабочая документация.
7. Ввод в действие.
8. Сопровождение АС.

### Международные стандарты

| Стандарт | Что регламентирует |
|----------|--------------------|
| ISO/IEC 12207 | Процессы жизненного цикла ПО |
| ISO/IEC 15288 | Процессы жизненного цикла систем |
| ISO 9001 | Управление качеством |
| CMMI | Модель зрелости процессов |

## 7. Что запомнить

- Жизненный цикл ИС — это период от идеи до вывода из эксплуатации.
- Этапы жизненного цикла: анализ → проектирование → разработка → тестирование → внедрение → сопровождение → вывод.
- Проектирование — это второй этап жизненного цикла. Оно включает проектирование архитектуры, базы данных, интерфейса, интеграций и безопасности.
- Основные стандарты: ГОСТ 34.601-90, ГОСТ 34.602-89, ISO/IEC 12207.
