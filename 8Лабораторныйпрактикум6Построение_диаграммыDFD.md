# Лабораторный практикум № 6
## Тема: Построение диаграммы потоков данных (DFD)

### Цель работы
Освоить методику структурного анализа информационных систем и приобрести практические навыки построения диаграмм потоков данных (DFD) для моделирования бизнес-процессов.

---

### Теоретическая часть

**DFD (Data Flow Diagram)** — это диаграмма потоков данных, которая описывает, как информация перемещается внутри системы: откуда она поступает, где обрабатывается, где хранится и куда передается. DFD не показывает последовательность действий во времени, а демонстрирует **функциональные зависимости** и **движение данных**.

**Основные элементы DFD:**

1. **Внешняя сущность (External Entity)** — объект или субъект (человек, организация, другая система), который является источником или получателем данных. Обозначается прямоугольником.
2. **Процесс (Process)** — действие по обработке, преобразованию или вычислению данных. Обозначается окружностью или овалом.
3. **Хранилище данных (Data Store)** — место для хранения данных (база данных, файл, реестр). Обозначается двумя параллельными линиями.
4. **Поток данных (Data Flow)** — направление передачи информации. Обозначается стрелкой с подписью, указывающей, какие именно данные передаются.

**Правила построения:**
*   Потоки данных не могут соединять две внешние сущности напрямую — они должны проходить через процессы.
*   Хранилища данных не могут сами «передавать» данные друг другу — между ними должен быть процесс.
*   Процесс должен иметь хотя бы один входящий и один исходящий поток.
*   Каждый поток должен быть подписан (что именно передается).

**Порядок построения:**
1.  **Контекстная диаграмма (уровень 0):** Вся система представляется одним процессом, вокруг которого располагаются внешние сущности.
2.  **Декомпозиция (уровень 1):** Главный процесс разбивается на более детальные подпроцессы, добавляются хранилища данных.
3.  **Детализация:** При необходимости каждый подпроцесс разбивается еще на более мелкие функции.

### Практическое задание

**Задание:** 
Необходимо разработать информационную систему для интернет-магазина по продаже электроники. Владелец магазина (Владелец) формирует каталог товаров. Клиент просматривает каталог и оформляет заказ. Система должна проверять наличие товара на складе, обрабатывать оплату через платежную систему (Платежный шлюз) и отправлять уведомление клиенту о статусе заказа. Информация о заказах должна сохраняться в базе данных.

**Что нужно сделать:**

1. **Постройте контекстную диаграмму (Уровень 0):**
   *   Изобразите систему как единый процесс «Интернет-магазин».
   *   Определите внешние сущности (например, Клиент, Владелец, Платежный шлюз).
   *   Покажите потоки данных между ними и системой (например, «Заказ», «Статус заказа», «Данные оплаты»).

2. **Постройте детализированную диаграмму (Уровень 1):**
   *   Разбейте процесс «Интернет-магазин» на подпроцессы:
       *   *Обработка заказа;*
       *   *Проверка наличия на складе;*
       *   *Обработка оплаты;*
       *   *Формирование уведомлений.*
   *   Добавьте **хранилища данных**:
       *   «Каталог товаров» (куда Владелец вносит изменения);
       *   «База заказов» (куда система записывает информацию).
   *   Соедините процессы, хранилища и внешние сущности **потоками данных** с подписями (что именно передается).

3. **Оформите отчет**, который должен содержать:
   *   Титульный лист.
   *   Цель работы.
   *   Краткие теоретические сведения (конспект).
   *   Диаграмму уровня 0 (контекстную) и диаграмму уровня 1 (декомпозицию).
   *   Описание каждого элемента (сущности, процессы, хранилища, потоки) в текстовом виде.
