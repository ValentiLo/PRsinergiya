# Лабораторный практикум № 7
## Тема: Построение диаграммы классов (UML Class Diagram)

### Цель работы
Освоить методику объектно-ориентированного проектирования и приобрести практические навыки построения диаграмм классов (Class Diagram) с использованием языка моделирования UML для описания статической структуры системы.

---

### Теоретическая часть

**Диаграмма классов (Class Diagram)** — это основной вид диаграмм в языке UML (Unified Modeling Language), который описывает **статическую структуру** системы: какие классы существуют, какие у них есть атрибуты и методы, а также как классы связаны между собой.

Диаграмма классов не показывает поведение системы во времени (как это делает, например, диаграмма последовательности), а фиксирует «скелет» объектной модели.

**Основные элементы:**

1. **Класс (Class)** — прямоугольник, разделенный на три части:
   *   **Имя класса** (вверху). Пишется с заглавной буквы.
   *   **Атрибуты / поля** (в середине) — данные, которые хранит объект.
   *   **Методы / операции** (внизу) — функции, которые умеет выполнять объект.
2. **Связи (Relationships)** — линии между классами. Основные типы:
   *   **Ассоциация (Association)** — обычная линия. Означает, что объекты одного класса знают о другом или связаны с ним.
   *   **Наследование / Обобщение (Generalization)** — стрелка с пустым треугольником, направленная на родителя. Означает «является разновидностью».
   *   **Композиция (Composition)** — линия с закрашенным ромбом. Означает «жесткую» связь, когда часть не может существовать без целого (например, Двигатель и Автомобиль).
   *   **Агрегация (Aggregation)** — линия с пустым ромбом. «Мягкая» связь, когда часть может существовать отдельно (например, Студент и Университет).
   *   **Зависимость (Dependency)** — пунктирная стрелка. Означает, что один класс временно использует другой (например, в параметрах метода).
3. **Множественность (Multiplicity)** — числа возле концов линий, показывающие, сколько объектов участвует в связи:
   *   `1` — ровно один.
   *   `0..1` — ноль или один.
   *   `*` (или `0..*`) — сколько угодно (много).
   *   `1..*` — один или больше.

**Порядок построения:**
1.  **Выделение сущностей:** Из текста задачи выписываются существительные, которые станут классами (например, «Студент», «Курс», «Преподаватель»).
2.  **Определение атрибутов:** Для каждого класса выписываются характеристики (поля).
3.  **Определение методов:** Для каждого класса описываются действия, которые он может выполнять.
4.  **Установление связей:** Определяется, как классы связаны между собой, проставляется множественность.

### Практическое задание

**Задание:**
Необходимо разработать объектную модель для автоматизированной системы **«Университетская библиотека»**.

В библиотеке есть книги (Книга), у каждой книги есть автор (Автор), название, уникальный ISBN и год издания. Книги могут выдаваться читателям (Читатель) на руки. Каждый читатель имеет номер читательского билета, ФИО и телефон. Выдача книги оформляется через запись о выдаче (Выдача), в которой фиксируется дата выдачи и дата возврата (если книга возвращена). Читатель может брать несколько книг, но одна физическая копия книги (Экземпляр) может быть выдана только одному читателю в текущий момент.

**Что нужно сделать:**

1.  **Выделите классы** на основе текста задания (минимум 5 классов).
2.  **Заполните каждый класс:**
    *   Имя.
    *   Атрибуты (с указанием типа данных: строка, число, дата).
    *   Методы (действия, которые логично выполняет класс).
3.  **Установите связи** между классами:
    *   Где нужно, используйте наследование.
    *   Определите тип связи (ассоциация, композиция, агрегация).
    *   Укажите множественность (например, 1 ко многим).
4.  **Оформите отчет:**
    *   Титульный лист.
    *   Цель работы.
    *   Краткая теория.
    *   Диаграмма классов (схема).
    *   Текстовое описание каждого класса и связей.

Разработать объектную модель для системы «Университетская библиотека». В библиотеке есть книги с авторами, читатели, а также процесс выдачи экземпляров книг читателям.

## 3. Выделенные классы и их структура

В ходе анализа предметной области были выделены следующие классы:

### Класс: Читатель (Reader)
*   **Атрибуты:**
    *   `readerId: int` — номер читательского билета
    *   `fullName: string` — ФИО
    *   `phone: string` — телефон
*   **Методы:**
    *   `getReaderInfo()` — получить информацию о читателе
    *   `takeBook(instanceId)` — взять книгу

### Класс: Книга (Book)
*   **Атрибуты:**
    *   `isbn: string` — уникальный номер
    *   `title: string` — название
    *   `year: int` — год издания
*   **Методы:**
    *   `getBookInfo()` — вывести информацию о книге

### Класс: Автор (Author)
*   **Атрибуты:**
    *   `authorId: int` — идентификатор
    *   `name: string` — имя автора
*   **Методы:**
    *   `getAuthorInfo()`

### Класс: Экземпляр (BookInstance)
*   **Атрибуты:**
    *   `instanceId: int` — уникальный номер экземпляра
    *   `status: string` — статус (в наличии / выдана)
*   **Методы:**
    *   `changeStatus(newStatus)` — изменить статус экземпляра

### Класс: Выдача (Loan)
*   **Атрибуты:**
    *   `loanId: int` — номер записи
    *   `issueDate: date` — дата выдачи
    *   `returnDate: date` — дата возврата
*   **Методы:**
    *   `closeLoan()` — закрыть выдачу (книга возвращена)

---

## 4. Связи между классами

1.  **Автор — Книга:** Ассоциация, «многие ко многим» (`*` — `*`). Один автор может написать много книг, одна книга может иметь несколько авторов.
2.  **Книга — Экземпляр:** Композиция (`1` — `1..*`). Одна книга (как абстрактное издание) имеет один или несколько физических экземпляров. Экземпляр не может существовать без книги.
3.  **Читатель — Выдача:** Ассоциация (`1` — `0..*`). Один читатель может иметь много выдач (история), но каждая выдача относится к одному читателю.
4.  **Экземпляр — Выдача:** Ассоциация (`1` — `0..1`). В один момент времени экземпляр может быть в одной активной выдаче.

> **Схема (Диаграмма классов):**
>
> ```text
> ┌──────────────┐        ┌────────────────┐
> │    Автор     │ *    * │     Книга      │
> │──────────────│────────│────────────────│
> │ authorId:int │        │ isbn:string    │
> │ name:string  │        │ title:string   │
> │──────────────│        │ year:int       │
> │ getInfo()    │        │──────────────  │
> └──────────────┘        │ getBookInfo()  │
>                         └───────┬────────┘
>                                 │ 1
>                                 │
>                                 │ Композиция
>                                 │
>                                 │ 1..*
>                         ┌───────▼────────┐
>                         │   Экземпляр    │
>                         │────────────────│
>                         │ instanceId:int │
>                         │ status:string  │
>                         │────────────────│
>                         │ changeStatus() │
>                         └───────┬────────┘
>                                 │ 1
>                                 │
>                                 │ Ассоциация
>                                 │
>                                 │ 0..1
> ┌──────────────┐        ┌───────▼────────┐
> │   Читатель   │ 1    * │    Выдача      │
> │──────────────│────────│────────────────│
> │ readerId:int │        │ loanId:int     │
> │ fullName:str │        │ issueDate:date │
> │ phone:string │        │ returnDate:date│
> │──────────────│        │────────────────│
> │ takeBook()   │        │ closeLoan()    │
> └──────────────┘        └────────────────┘
> ```

---

## 5. Описание логики связей

*   Связь **Книга — Экземпляр** реализована как **композиция**, так как физический экземпляр (конкретный том) является неотъемлемой частью библиотечного фонда и не может существовать без описания самой книги.
*   Связь **Читатель — Выдача** реализована как **ассоциация** с множественностью `0..*`, так как у читателя может быть история выдач, и он может не иметь активных выдач в данный момент.
*   Связь **Экземпляр — Выдача** показывает, что один конкретный экземпляр может быть в процессе выдачи только один раз (множественность `0..1` со стороны выдачи), но за всю историю у него может быть много выдач.
