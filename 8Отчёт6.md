## 1. Цель работы
Освоить методику структурного анализа информационных систем и приобрести практические навыки построения диаграмм потоков данных (DFD) для моделирования бизнес-процессов.

## 2. Постановка задачи
Разработать модель информационной системы для интернет-магазина электроники. Владелец магазина формирует каталог товаров. Клиент просматривает каталог и оформляет заказ. Система должна проверять наличие товара на складе, обрабатывать оплату через платежную систему и отправлять уведомление клиенту. Информация о заказах сохраняется в базе данных.

---

## 3. Контекстная диаграмма (Уровень 0)

На контекстной диаграмме вся система представлена как единый процесс. Определены основные внешние сущности и потоки данных между ними.

**Внешние сущности:**
*   **Клиент** — просматривает каталог, оформляет заказ, получает уведомления.
*   **Владелец** — управляет каталогом товаров.
*   **Платежный шлюз** — проводит оплату.

**Основные потоки данных:**
*   Владелец \(\rightarrow\) Система: *Данные о товаре*
*   Клиент \(\rightarrow\) Система: *Запрос каталога, Данные заказа*
*   Система \(\rightarrow\) Клиент: *Каталог товаров, Статус заказа*
*   Система \(\rightarrow\) Платежный шлюз: *Запрос на оплату*
*   Платежный шлюз \(\rightarrow\) Система: *Подтверждение оплаты*

> **Схема (Уровень 0):**
>
> ```text
>  [Владелец] ──(Данные о товаре)──> ╭────────────────────────╮
>                                    │                        │
>    [Клиент] ──(Запрос каталога)──> │      ИНТЕРНЕТ-МАГАЗИН  │ ──(Каталог)──> [Клиент]
>    [Клиент] ──(Данные заказа)────> │                        │ ──(Статус)───> [Клиент]
>                                    │         (Система)      │
>                                    ╰──────────┬─────────────╯
>                                               │
>                                     (Запрос оплаты) │ (Подтверждение)
>                                               ▼
>                                       [Платежный шлюз]
> ```

## 4. Детализированная диаграмма (Уровень 1)

Главный процесс «Интернет-магазин» разбит на 4 подпроцесса и дополнен хранилищами данных.

**Процессы:**
1.  **П1. Обработка заказа** — принимает данные от клиента, формирует заказ.
2.  **П2. Проверка наличия на складе** — обращается к каталогу товаров.
3.  **П3. Обработка оплаты** — взаимодействует с платежным шлюзом.
4.  **П4. Формирование уведомлений** — отправляет статус клиенту.

**Хранилища данных:**
*   **Х1. Каталог товаров** — хранит информацию о товарах, остатках на складе.
*   **Х2. База заказов** — хранит историю и статусы всех заказов.

**Потоки данных:**
*   Владелец \(\rightarrow\) **Х1** (Данные о товаре)
*   Клиент \(\rightarrow\) **П1** (Данные заказа)
*   **П1** \(\rightarrow\) **Х2** (Новый заказ)
*   **П1** \(\rightarrow\) **П2** (Запрос на проверку)
*   **П2** \(\leftrightarrow\) **Х1** (Запрос остатков / Ответ)
*   **П2** \(\rightarrow\) **П3** (Товар в наличии)
*   **П3** \(\leftrightarrow\) Платежный шлюз (Запрос / Подтверждение)
*   **П3** \(\rightarrow\) **П4** (Оплата прошла)
*   **П4** \(\rightarrow\) **Х2** (Обновить статус)
*   **П4** \(\rightarrow\) Клиент (Уведомление о статусе)

> **Схема (Уровень 1):**
>
> ```text
> [Владелец] ──(Данные о товаре)──> ╔══════════════════╗
>                                   ║  Х1. Каталог     ║
>                                   ║     товаров      ║
>                                   ╚═════════╤════════╝
>                                             │ (Запрос / Ответ)
> [Клиент] ──(Данные заказа)──> ( П1 ) ───────┼──────────> ( П2 )
>                               Обработка      │            Проверка
>                               заказа         │            наличия
>                                 │            │               │
>                                 │ (Новый     │               │ (Товар
>                                 │  заказ)    │               │  в наличии)
>                                 ▼            │               ▼
>                            ╔════════════╗    │         ( П3 )
>                            ║ Х2. База   ║    │         Обработка
>                            ║   заказов  ║    │         оплаты
>                            ╚═════╤══════╝    │               │
>                                  ▲           │               │ (Запрос/
>                                  │ (Обновить │               │  Ответ)
>                                  │  статус)  │               ▼
>                               ( П4 )         │       [Платежный шлюз]
>                            Формирование      │
>                            уведомлений       │
>                                  │            │
>                                  ▼            │
>                             [Клиент] ─────────┘
>                            (Уведомление)
> ```

## 5. Описание элементов диаграммы

| Элемент | Тип | Описание |
| :--- | :--- | :--- |
| **Клиент** | Внешняя сущность | Пользователь, который ищет товар, оформляет заказ и получает уведомления. |
| **Владелец** | Внешняя сущность | Администратор, который наполняет каталог товаров и управляет остатками. |
| **Платежный шлюз** | Внешняя сущность | Сторонняя система для проведения финансовых транзакций. |
| **П1. Обработка заказа** | Процесс | Валидация данных клиента, формирование структуры заказа. |
| **П2. Проверка наличия** | Процесс | Сверка запрошенного товара с текущими остатками в каталоге. |
| **П3. Обработка оплаты** | Процесс | Инициирование транзакции и получение подтверждения от шлюза. |
| **П4. Формирование уведомлений** | Процесс | Сборка текста уведомления и отправка его клиенту. |
| **Х1. Каталог товаров** | Хранилище | Таблица с описанием товаров, цен и количества на складе. |
| **Х2. База заказов** | Хранилище | Таблица с историей заказов и их текущими статусами. |

## 6. Вывод

В ходе выполнения лабораторной работы была построена модель информационной системы интернет-магазина с использованием методологии DFD. 
Были выделены внешние сущности (Клиент, Владелец, Платежный шлюз), определены основные процессы обработки данных (обработка заказа, проверка склада, оплата, уведомление) и обозначены хранилища данных (каталог и база заказов). 
Диаграмма уровня 0 демонстрирует общую концепцию системы, а диаграмма уровня 1 детализирует внутренние потоки информации, что позволяет разработчикам четко понять, как данные циркулируют внутри будущей программы.
